## Transaction boundaries and failure rules

1. Setup locks the singleton and consumes the local invitation atomically with owner creation.
2. Bootstrap checks invitation expiry, revocation and device association; consumes invitation and records the new identity in one transaction. Failed network delivery cannot duplicate inventory.
3. Scope/access mutation increments revision and cancels queued grants. Workers revalidate immediately before connecting and before privileged steps; pause acknowledgement fences new leases.
4. Enrollment claims a server lease and a target-local installation lock. An expired server lease requires target-journal reconciliation before another install; completion requires authenticated agent telemetry.
5. Telemetry validates a whole batch before atomically storing receipt plus samples. No partial success without an explicit per-item protocol revision. Duplicates with identical payloads do not create new observations.
6. Revocation marks the identity and prevents new jobs atomically with a persistent exclusion. History retention cannot remove the exclusion.
7. Restoring an old backup cannot resurrect active execution: recovery mode remains in effect until owner reconciliation. All sessions are invalidated on restore; certificate/revocation reconciliation is explicit.

## Validation and retention

Use the limits and intervals in plan.md. Reject non-finite numeric samples, negative capacities, invalid CIDRs, expired job reports, unexpected identity claims, and oversize payloads. Counter reset produces an unavailable rate for that interval, not a negative throughput. CPU and used/total percentages must stay within 0–100; any source anomaly is a collector diagnostic.

Raw measurements expire after the configured default 30 days; audit after 90 days. Latest device identity, exclusions, revocations, and current policies have no time-based deletion. Delete unreachable release blobs only when no current assignment or supported rollback slot requires them. Report orphan cleanup explicitly. Credentials deleted by the owner become unusable for new jobs immediately; retained encrypted backup copies follow backup policy and documented key destruction limits.
